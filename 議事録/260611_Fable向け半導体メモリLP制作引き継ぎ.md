# Fable向け半導体メモリLP制作引き継ぎ

## 目的

GitHubに置いている半導体メモリ検査工程のExcel自動化実績を、転職採用担当・技術職面接官向けのホームページ風ページにする。

このページで伝えたい中心は、ExcelやVBAそのものではない。

伝えたい人物像は、**非エンジニア業務を構造化できるIT人材**。

属人的な手作業を観察し、情報設計・ルール化・自動処理に変換できる人として見せる。

## Fableに伝える制作方針

- 採用向けポートフォリオページとして作る。
- 派手な営業LPではなく、落ち着いた技術ポートフォリオ風にする。
- 主役は「作業時間を短縮した改善ストーリー」。
- Excel関数・VBA・命名規則は、改善ストーリーの裏付けとして扱う。
- Excel職人ではなく、現場課題を構造化して改善した人に見える構成にする。
- 会社名、製品名、実測値、内部条件は出さない。
- 「完全に防止」「保証」「ゼロにした」などの断定表現は避ける。

## 制作ループ

1. **Loop 1: grill-meで構成を厳しく詰める**
   - 読者、見せたい人物像、ページ構成、避ける表現を決める。

2. **Loop 2: Fableでページ本文を作る**
   - Fableには、採用向けホームページ風の本文、見出し、導線を作らせる。

3. **Loop 3: lp-productionでHTMLセクション構成に変換する**
   - Fableの文章を、`section`、`h1`、`h2`、`p`、`ul`、CTA単位に整理する。

4. **Loop 4: stop-slopで自然な採用向け文章に整える**
   - AIっぽい前置き、過剰表現、抽象的すぎる表現、断定表現を削る。

5. **Loop 5: Codexでindex.html / style.cssに反映する**
   - 既存のポートフォリオHTMLとCSSへ反映し、表示を確認する。

## ページ構成

1. ファーストビュー
2. 業務背景

## ファーストビュー

### 見出し案

```txt
属人的な“探す・読む・転記する”検査記録作業を、再現できる業務フローへ整理したExcel自動化
```

### サブコピー案

```txt
半導体メモリ検査工程の破断面観察業務で、画像ファイル名と管理台帳をつなぐ仕組みを設計。手作業で3〜4時間かかっていた記録作業を、約45分まで短縮しました。
```

## 業務背景

専門用語は避けすぎない。読者が改善価値を理解するための前提知識は入れる。

### 入れる内容

- 半導体メモリは、ウェハ上に多数のチップを形成する。
- 後工程でチップを1つずつ切り出し、ピックアップして扱う。
- チップは薄く小さいため、欠け・割れ・微細なダメージが問題になる場合がある。
- ウェハ上の位置や製造条件によって、割れやすさに差が出ることがある。
- 歩留まりは1文だけ説明する。
- そのため、サンプルに力をかけたときの破断状態を記録し、位置・条件・破断面の関係を確認していた。

### 本文案

```txt
半導体メモリは、ウェハ上に多数のチップを形成し、後工程で1つずつ切り出して扱います。チップは薄く小さいため、切り出しやピックアップ時の負荷によって、欠け・割れ・微細なダメージが問題になる場合があります。

また、ウェハ上の位置や製造条件によって、チップの割れやすさに差が出ることがあります。半導体製造では、良品として次工程や出荷へ進められる割合である「歩留まり」を高めることが重要です。

そのため、サンプルに力をかけたときの破断状態を記録し、位置・条件・破断面の関係を確認していました。
```

## 改善前の課題

主役は、「集中力がいるのに、誰がやってもミスが起こりそうな作業設計だったこと」。

### 見出し案

```txt
集中力に頼る手順が、標準作業になっていた
```

### 入れる内容

- 単純作業に見えて、実際は認知負荷が高かった。
- 画像撮影、測定値確認、ファイル名入力、Excel台帳への転記を1件ずつ行っていた。
- 1,000行超の管理台帳から正しい行を探す必要があった。
- 課題は作業者の注意力ではなく、人が毎回“探す・照合する・転記する”ことを前提にした作業設計にあった。
- ミスを防ぐには、注意力ではなく作業設計を変える必要があった。

### 本文案

```txt
改善前の記録作業は、単純な入力作業に見えて、実際には認知負荷の高い作業でした。画像撮影、測定値確認、ファイル名入力、Excel台帳への転記を1件ずつ行い、1,000行超の管理台帳から正しい行を探して対応づける必要がありました。

課題は、作業者の注意力ではありません。人が毎回“探す・照合する・転記する”ことを前提にした作業設計にありました。ミスを防ぐには、作業者がさらに注意するのではなく、手順そのものを見直す必要があると考えました。
```

## 工夫した仕組み

### 見出し案

```txt
画像ファイル名を、Excelが読める入力フォームとして使った
```

### 入れる内容

- 測定器とExcel台帳を直接連携できない制約があった。
- 画像ファイル名にサンプル番号や条件など、台帳照合に必要な情報を埋め込む命名規則を作った。
- Excel関数とVBAで、ファイル名から情報を自動抽出した。
- 抽出した情報を使い、管理台帳の該当行へ照合・転記できるようにした。
- 現場で使えるExcelとファイル名設計で、データ連携に近い状態を作った。

### 本文案

```txt
測定器とExcel台帳を直接連携できない制約があったため、画像ファイル名にサンプル番号や条件など、台帳照合に必要な情報を埋め込む命名規則を作りました。

そのうえで、Excel関数とVBAを使ってファイル名から情報を自動抽出し、管理台帳の該当行へ照合・転記できるようにしました。

人が毎回“探す・照合する・転記する”のではなく、現場で使えるExcelとファイル名設計だけで、データ連携に近い状態を作ったことが工夫点です。
```

## なぜ短縮できたのか

説明の因果は、次の順番で固定する。

1. **現場負担**
   - 1,000行超の台帳から正しい行を探す時間が大きかった。
   - PC間を行き来する手入力の負担が大きかった。

2. **仕組み**
   - 画像ファイル名から必要情報を抽出した。
   - Excel関数とVBAで照合・転記を自動化した。

3. **改善後の作業設計**
   - 全件を人が探して入力する作業から、自動処理された結果を確認する作業フローへ変えた。

### 本文案

```txt
改善前は、画像撮影や測定値確認のたびに、1,000行超の管理台帳から対象サンプルの行を探し、PC間を行き来しながら手入力していました。

改善後は、画像ファイル名に埋め込んだ情報をExcel関数とVBAで抽出し、該当行への照合・転記を自動化しました。

これにより、作業者が毎回“探す・照合する・入力する”時間を大きく減らし、自動処理された結果を確認する作業フローへ変えることができました。
```

## 成果

成果は、時間短縮を大きく見せる。認知負荷、転記ミス・行ズレ、再現性は短く添える。

### 本文案

```txt
手作業で3〜4時間かかっていた記録作業を、約45分まで短縮しました。

あわせて、常に注意力を使い続ける負担や、転記ミス・行ズレが起きやすい作業構造も見直しました。詳細な設計・処理内容は、GitHubのREADMEに整理しています。
```

使う強みは2つに絞る。

- 現場の手作業を、情報設計と自動化に分解できる。
- 業務背景を理解して、改善対象を見極められる。

### 本文案

```txt
この実績で伝えたいのは、ExcelやVBAそのものではなく、現場の手作業を観察し、どこに負担やミスの入り込む余地があるかを見極めたうえで、情報設計と自動化に分解できることです。

半導体メモリ検査工程という専門性のある業務でも、作業の流れを整理し、「人が判断すべきこと」と「仕組みで処理できること」を切り分けることで、再現性のある改善につなげました。
```

## 禁止・注意表現

### 出さない情報

- 会社名
- 製品名
- 実測値
- 内部条件
- 原因断定
- 現場固有の専門用語の出しすぎ

### 避ける表現

- 完全に防止
- 保証
- ゼロにした
- 必ず防げる
- 原因はこれだった

### 使いやすい表現

- 低減した
- 減らした
- 起きにくい構造にした
- つながる場合がある
- 傾向を見る
- 関係を確認する
- 手がかりにする

## Fable出力後の確認観点

- 採用担当者にも業務背景が分かるか。
- 技術職面接官にも工夫点が伝わるか。
- Excel/VBAの話に寄りすぎていないか。
- 「非エンジニア業務を構造化できるIT人材」に見えるか。
- 3〜4時間から約45分へ短縮できた理由が伝わるか。
- 会社名、製品名、実測値、内部条件に見える表現がないか。
- 断定表現がないか。
- GitHub READMEへ自然に誘導できているか。
