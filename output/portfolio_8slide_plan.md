# 採用担当者向け 8枚スライド構成案

想定形式: Canva / PPTX / PDF化しやすい 16:9 横長スライド  
作成方針: 1枚1テーマ、本文は短く、図解で「Before / After」と「3〜4時間 → 約45分」を見せる  
公開方針: 会社名、実製品名、実型番、実測値、内部資料に見える画像は出さない

---

## Slide 1: 成果の全体像

### 一言メッセージ
検査記録の手入力作業を、仕組み化で **3〜4時間 → 約45分** に短縮しました。

### 本文
- 検査画像の記録作業では、1,000行超の台帳から正しい行を探す必要がありました。
- ファイル名の命名規則、表計算ソフトの関数、マクロを組み合わせて自動化しました。
- 手入力と目視確認に頼る流れを、ファイル名から読み取って台帳へ反映する流れに変えました。
- 現場の困りごとを「注意力」ではなく「仕組み」で改善した事例です。

### 画像・図解指示
- 左に Before、右に After の2分割図。
- 中央または下部に **3〜4時間 → 約45分** を最大サイズで配置。
- Before 側は「目視で探す」「手入力」「確認ループ」、After 側は「命名規則」「自動抽出」「自動転記」をアイコン化。

### Canva / PPTX配置指示
- 16:9、白背景または薄いグレー背景。
- 上部に短いタイトル、中央に大きな時間短縮、下部に Before / After の横並び。
- 数字を主役にし、本文は4行以内の小さな補足にする。

### 公開注意点
- 実際の会社名、製品名、実測値、実ファイル名は入れない。
- 「完全自動化」「ミスゼロ」ではなく、「負担を減らした」「確認しやすくした」と表現する。

## Slide 2: 改善前に起きていたこと

### 一言メッセージ
一番重かったのは、入力そのものより「正しい行を探して確認する」作業でした。

### 本文
- 画像を撮影したあと、数十件分の結果を管理台帳へ記録していました。
- 台帳は1,000行を超え、該当する行を目視で探す必要がありました。
- 行を見つけて入力し、さらに転記ミスがないかを確認していました。
- 行ズレや入力漏れが起きると、後続の集計作業にも手戻りが発生しました。

### 画像・図解指示
- 「画像フォルダ」「1,000行超の台帳」「作業者の目視確認」を横に並べる。
- 台帳の中に小さなハイライト行を置き、「ここを探す」が大変だと見せる。
- 「探す → 入力 → 確認」の矢印を入れる。

### Canva / PPTX配置指示
- 左側に作業フロー図、右側に課題の短文3点。
- 台帳イメージは細かい文字を入れず、行が多い見た目だけで伝える。
- 強調語は「1,000行超」「目視」「手戻り」の3つに絞る。

### 公開注意点
- 実際の台帳スクリーンショットは使わない。
- 行数は「1,000行超」とし、内部の列名や識別子は出さない。

## Slide 3: なぜ3〜4時間かかっていたのか

### 一言メッセージ
時間を奪っていたのは、入力後の確認・修正・再確認のループでした。

### 本文
- 数十件のデータを扱うため、1件の行ズレが全体の見直しにつながりました。
- 入力後に、転記ミスがないかを再度目視で確認する必要がありました。
- ミスを見つけると、修正してからもう一度確認する流れになっていました。
- 原因は作業者個人ではなく、間違えても気づきにくい作業設計にありました。

### 画像・図解指示
- 円形ループで「入力 → 確認 → 修正 → 再確認」を表す。
- ループ中央に「確認コストが大きい」と配置。
- ループ外に「3〜4時間」のラベルを置き、時間が積み上がる印象にする。

### Canva / PPTX配置指示
- 中央に大きなループ図、右下に補足テキスト。
- 色は Before を薄い赤やオレンジ、After につながる改善余地を青や緑で示す。
- 文章量を抑え、ループ図だけで課題が伝わる構成にする。

### 公開注意点
- 「作業者のミスが原因」と読める表現は避ける。
- 「ミスが頻発」よりも「ミスに気づきにくい構造」と表現する。

## Slide 4: 解決の発想

### 一言メッセージ
画像ファイル名を、後工程で読み取れる「小さなデータベース」として設計しました。

### 本文
- 画像保存時のファイル名に、必要な情報を決まった順番で埋め込みました。
- 型番、位置、番号、方向、測定値、状態を、公開用のダミー形式で表せるようにしました。
- 人が台帳へ直接入力するのではなく、仕組みがファイル名から読み取る形に変えました。
- 上流の命名ルールを整えることで、後工程の転記ミスを減らしやすくしました。

### 画像・図解指示
- ダミー例: `AA-00TP01A_XXum_状態A.jpg`
- ファイル名を色分けし、「型番」「位置」「番号」「方向」「測定値」「状態」へ分解する。
- 下部に「ファイル名 = 後工程で読めるデータ」と短く入れる。

### Canva / PPTX配置指示
- 横長のファイル名を中央に大きく置き、各部分から吹き出しを伸ばす。
- 実測値部分は `XX` や `X.XX` のような伏せ字にする。
- 1枚の中で最も視線が集まる場所をファイル名分解図にする。

### 公開注意点
- 実型番や実測値に見える文字列は使わない。
- ダミー例であることが分かるように「公開用サンプル」と小さく添える。

## Slide 5: 作った仕組み

### 一言メッセージ
フォルダ内の画像名を一覧化し、項目を抽出して、正しい行へ反映する流れを作りました。

### 本文
- マクロで画像フォルダを選び、ファイル名を一覧として取り込みます。
- 関数でファイル名から必要な項目を抽出します。
- 抽出した項目を組み合わせて、台帳側の行と照合するキーを作ります。
- 測定値と状態を、1,000行超の台帳の該当行へ反映しやすくしました。

### 画像・図解指示
- 4ステップの横流れ図にする。
- 1. フォルダ選択
- 2. ファイル名一覧化
- 3. 項目抽出
- 4. 台帳へ反映
- 3と4の間に「複合キーで照合」という小さなラベルを入れる。

### Canva / PPTX配置指示
- 横4分割のプロセス図。
- 各ステップはアイコン + 8文字前後のラベル + 1行説明にする。
- 技術名は小さく補足し、主語は「作業の流れ」に置く。

### 公開注意点
- 実際のシート名、内部フォルダ名、実台帳名は使わない。
- 「自動転記」は使ってよいが、「完全に正しい」と保証する言い方は避ける。

## Slide 6: 技術的な工夫

### 一言メッセージ
単に動くだけでなく、現場で使いやすく、確認しやすい形に寄せました。

### 本文
- 固定位置だけに頼らず、目印になる文字を探して値を取り出すようにしました。
- 想定外の入力はエラー表示だけにせず、「該当なし」として見つけやすくしました。
- 古い環境でも動きやすいよう、使う関数を現場の環境に合わせました。
- 複数の項目を組み合わせたキーで、台帳の該当行と照合しました。

### 画像・図解指示
- 「壊れにくくする工夫」を3カードで表示。
- カード1: 目印から抽出
- カード2: 該当なしで見える化
- カード3: 複合キーで照合
- 下部に「詳細はREADME / 関数設計資料へ」と小さく誘導。

### Canva / PPTX配置指示
- 3枚カードを横並びにし、各カードはアイコン + 見出し + 1行説明。
- 数式そのものは載せず、必要なら脚注レベルに留める。
- 採用担当者が読んでも詰まらないよう、専門語は補足つきにする。

### 公開注意点
- 長い数式をそのまま貼らない。
- 内部の識別コードや実データが入った画面キャプチャは使わない。

## Slide 7: 改善結果

### 一言メッセージ
手作業中心の記録が、短時間で確認しやすい運用に変わりました。

### 本文
- 作業時間は **3〜4時間 → 約45分** に短縮しました。
- 1,000行超の台帳から目視で正しい行を探す負担を大きく減らしました。
- 転記ミスや再確認の負担を減らし、後続の集計手戻りも起きにくくしました。
- 業務報告でも、現場課題を仕組みで改善した点が評価されました。

### 画像・図解指示
- Before / After 表を中央に置く。
- 行項目は「作業時間」「行探し」「確認負担」「後続作業」の4つ。
- 右上に再度 **3〜4時間 → 約45分** を大きく表示。

### Canva / PPTX配置指示
- 表は2列比較にし、After 側を強調色で見せる。
- 数字と「1,000行超」を太字にする。
- 文字が多くならないよう、各セルは短いフレーズだけにする。

### 公開注意点
- 「ミスをなくした」ではなく「負担を減らした」「起きにくくした」と書く。
- 評価については「業務報告で評価された」程度に留め、社内評価制度名は出さない。

## Slide 8: この経験から得た強み

### 一言メッセージ
現場の違和感を観察し、ミスが起きにくい仕組みへ落とし込めることが自分の強みです。

### 本文
- 手作業のつらさを、個人の注意力ではなく業務フローの問題として捉えました。
- ファイル名、台帳、関数、マクロを一連の流れとして設計しました。
- 限られたツールでも、現場で使える改善を形にできました。
- 今後はこの経験を、ソフトウェア開発やAI活用による業務改善へ広げていきたいです。

### 画像・図解指示
- 「現場理解 → 仕組み化 → 自動化 → 再利用」の4ステップを横に並べる。
- 最後に GitHub / README / ポートフォリオLP への導線を配置する。
- 人物写真ではなく、抽象的なワークフロー図やアイコンでまとめる。

### Canva / PPTX配置指示
- 左に4ステップ図、右に「強み」3点の短い箇条書き。
- 最下部にリンク導線を小さく置く。
- 最終スライドなので、余白を広めに取り、結論が残る構成にする。

### 公開注意点

- 公開リンク先にも機密に見える固有名詞や実データが無いか確認する。
