# Portfolio Slide Structure

Use this skill to turn a technical portfolio project into a concise slide plan for hiring reviewers.

## Workflow

1. Read the user-provided harness first, then the source Markdown files.
2. Extract only the story needed by a non-engineer: problem, cause, idea, mechanism, result, and strength.
3. Split into exactly 8 slides with one theme per slide.
4. For each slide, include:
   - slide number
   - title
   - one-line message
   - 3-5 short body lines
   - image or diagram direction
   - Canva/PPTX layout direction
   - public-release caution
5. Emphasize measurable impact without overclaiming.
6. Run a checklist against the user's acceptance criteria and revise before saving.

## Writing Rules

- Make the first slide show the main result immediately.
- Keep formulas and implementation detail light; use them as evidence, not the main story.
- Use terms a hiring reviewer can understand before naming technical methods.
- Prefer "reduced", "made easier to check", "made it easier to transfer to the right row" over absolute claims.
- Avoid company names, real product names, real measurements, internal identifiers, and anything that looks confidential.
- Use dummy examples when showing file names or tables.
- Avoid blaming workers; frame the issue as a workflow design problem.

## Recommended 8-Slide Arc

1. Overall result
2. Before: what was happening on site
3. Root cause: searching and checking cost
4. Core idea: make filenames structured data
5. Built workflow: list, extract, match, transfer
6. Design details: robustness and compatibility
7. After: results and before/after comparison
8. Career value: strength as a developer
